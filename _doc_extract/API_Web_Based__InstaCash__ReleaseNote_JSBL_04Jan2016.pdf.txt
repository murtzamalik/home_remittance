 As Transaction gets ready for Payment and user hits process system first it checks that 
user is authorized to process transaction of following “xyz” figure amount.  If the login 
user or teller is authorized to do Payment of available “xyz” figure amount than 
following described flow of payment will be executed.  Vice-versa scenario will be 
analyzed later. 
 
 As user is authorized, So Initially Fund Transfer performed through “JSBL Web Service 
“at its own end.  
 
 At COTC Interface initially JSBL Web Service performs Fund Transfer call from 
“Remitting Entity NR Account” to “JSBL Payable Account”. This fund transfer call is 
basically transfer the Funds from available remitting entity account to JSBL payable. 
  
 At back end data base “Message LOG “updated that logs the information that COTC 
interface sent to JSBL Web Service and also the response that JSBL web service returns. 
  
 If response from JSBL web service is positive (successful) than only transaction is 
forwarded to remitting entity’s Web Service to do payment at its own end,  otherwise 
unsuccessful response from  JSBL Web Service halts further processing and message 
pops up at the screen  that “JSBL web service fund transfer failed due to xyz reason”. 
Screen View is available below:

 As teller now see “Transaction was paid: it means JSBL Web Service  web service and Exchange 
Company’s  web Service both provide successful response. (Payment from remitting entity side 
also executed successfully), Engine has created General transaction at back end DB and new 
record logged in PRI marked as “Paid” and transaction get paid successfully.  
 
 If remitting entity couldn’t able to process fund transfer successfully than reason of failure 
displayed at the interface, and in this case JSBL Fund Transfer reversal call occurred against the 
previous successful attempt.  Message log get updated against reversal at back end db. In the 
root’s web.config  file following key needed to place:  
<add key="revrsalAttempt" value="3"/> 
The reason for this flag is if reversal atttempt is not successful once than we do more than one 
attempts to do reversal. 
 Also add the key mentioned below in the application web. config file to set expiry time for cash 
transactions. Value for pay timeout will be in minutes. In case of transaction expiry transaction 
will be once again created. 
       <add key="Paytimeout" value="15"/>
