The emphasis of this document is on the business requirements of Home Remit FT and IBFT transaction. In order to design the system that meets all of the business requirements, in this document data flow diagrams have been provided which clearly shows flow of information between various systems involved in the process. 
Moreover, failure of transaction case has also been covered in this document mentioning all of the steps that will be performed during a single Home Remit FT and IBFT transaction. 
In order to accomplish the Home Remit FT and IBFT transaction, development will be required at T24 level which is presented in a step by step manner in this document. 
Successful scenario       
Sub Agent IBFT Transaction scenario 
Home Remit System will send Title Fetch request to 1LINK
1LINK will respond to the Title Fetch request
Home Remit System on 1LINK
s response will send FT request to T24 through calling of API, the transaction description (such as transaction type, date/time and STAN format given on page no 9) will be saved at T24 as input mode 
The FT request will stand in the queue at T24 system 
T24 system will identify the Home Remit sub agent transaction based on special character 
Home Remit System will authorize the transaction
Home Remit System will send IBFT advice and FT transaction message data elements to T24
T24 will check the FT transaction message data elements with the relevant FT transaction description that is saved as input mode at T24, after verification T24 system will debit exchange company account and credit 1LINK suspense account 
T24 system will than send successful response message to 1LINK through API to execute the advice transaction
Agent IBFT Transaction scenario 
s response will send IBFT request to T24 though calling API
T24 system will identify the Home Remit agent transaction based on special character
Home Remit System will send IBFT advice and IBFT transaction message data elements 
T24 system will debit exchange company account and credit 1LINK suspense account 
Sub Agent FT Transaction scenario 
Home Remit System will send Title Fetch request to JS Bank
JS Bank will respond to the Title Fetch request
Home Remit System on JS Bank
s response will send FT request through calling different FT API, the transaction description (such as transaction type, date/time and STAN format given on page no 7) will be saved at T24 as input mode 
Home Remit System will send FT advice and FT transaction message data elements to T24
T24 will check the FT transaction message data elements with the relevant FT transaction description that is saved as input mode at T24, after verification T24 system will debit exchange company account and credit JS Bank account 
T24 system will than send successful response message through calling API to execute the advice transaction
Un-Successful scenario       
s response will send FT request to T24 through calling of API
The timer of authorization expiry starts at Home Remit System
The timer indicates transaction expiry at Home Remit System before receiving reply from T24
Home Remit sub agent will send an e-mail to T24 and similarly mark those expired transactions in the queue at Home Remit System manually to be deleted from the system 
Inquiry module has to be implemented at T24 end which will allow to manually delete expired transactions based on transaction details i.e. date and time field and STAN received an e-mail from Home Remit sub agent
The expiry of transaction scenario will be same for both FT and IBFT transaction, however different queues will be maintained i.e. one for FT expiry transactions and another for IBFT expiry transactions. Similarly, e-mail will be generated to T24 for manually deleting the relevant expiry transaction from T24 system.

Expiry of Authorization time scenario (Sub Agent IBFT and FT transaction)
Description:
The above diagram depicts a scenario where authorization of transaction time expires. After sending FT request to T24 the authorization timer starts, if response is not received within the defined timeline than expired transaction will be e-mailed by sub agent of Home Remit System as well as transactions will be marked manually in the Home Remit System to be deleted from the system. Similarly, inquiry module will be implemented at T24 which will allow deleting the expired transaction based on its data field (date/time and STAN) at T24 manually received in the e-mail from Home Remit System sub agent. 
Please note that the above scenario will be same for both FT transaction and IBFT transaction. The only difference will be maintenance of different queues that is in case of FT transaction expiry different queue will be maintained to that of IBFT expired transaction queue.

Different limit will be managed at sub agent and agent IBFT transaction as well as at sub agent and agent FT transaction.

The system will incorporate per user account mapping based on exchange companies. That is each exchange company user will be able to access certain accounts.
