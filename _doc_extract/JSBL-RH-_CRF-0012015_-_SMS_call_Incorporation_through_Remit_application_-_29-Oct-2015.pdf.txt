Brief Description of Changes:  
 
Changes required in:        ○ Program           ○ Database             
Scope Of Work :  
 
1. Currently JSBL is using its own SMS mechanism. The same mechanism will be used by them and SMS 
will not be send by Remit application. 
2. SMS incorporation will be dependent on JSBL provided information like database, DSN, table format 
etc. 
3. As per requested by JSBL what Remit application will do is that it will insert SMS call in JSBL 
provided database’ table.  
4. SMS incorporation will be done on status(es) and transaction mode. 
5. For all the status(es) and transaction mode(s) for which entry is made  remit application will call the 
JSBL provided table through JSBL provided DSN and if available then will insert the data in that 
particular table. 
6. Remit application job will be enter/insert data in JSBL provided table and will also retain that 
transaction/record in remit application so that user can re‐send the data from newly developed 
interface. 
7. In‐case if table is not accessible then such transaction will be inserted in a new table at remit 
application. These transactions will be available at a newly developed interface and user will have 
the facility to re‐send/insert them from there in JSBL table. 
8. SMS messages against statuses and mode of transaction will be configurable as user may change 
these messages in future. 
9. Data asked to be inserted in JSBL table will be according to the information provided requirement 
specification document. 
• ID    Unique Reference Number 
• Cell    Beneficiary Mobile Number 
• Message   Customized message against status and mode. 
• Entry Date   Insertion date 
• FLAG   N ‐ Fixed 
• Transaction Nature  C – Fixed 
• Transaction Type  Mode of transaction 
• Channel   RH
