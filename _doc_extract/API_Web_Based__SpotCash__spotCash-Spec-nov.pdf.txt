Overview	  
spotCash!	  is	  the	  flagship	  Money	  Transfer	  product	  offered	  by	  Placid	  Express.	  Access	  
to	  the	  product	  by	  correspondents	  is	  provided	  through	  either	  an	  API	  or	  by	  use	  of	  the	  
company’s	  dedicated	  web	  based	  platform.	  
Money	  Transfer	  transactions	  conducted	  through	  the	  spotCash!	  Product	  are	  held	  at	  a	  
virtual	  repository	  within	  the	  company’s	  Global	  Order	  Processing	  Hub	  (GOPH)	  
platform.	  Disbursements	  of	  transactions	  are	  made	  possible	  by	  correspondents	  
utilizing	  a	  dedicated	  Web	  Services	  API	  or	  by	  using	  a	  Web	  Based	  Payment	  System.	  	  
spotCash!	  differs	  from	  other	  cash	  based	  payments	  in	  a	  number	  of	  ways.	  The	  most	  
important	  difference	  lies	  with	  how	  transactions	  are	  communicated	  to	  
correspondents.	  With	  spotCash!,	  the	  transactions	  will	  need	  to	  be	  PULLED	  instead	  of	  
Placid	  Express	  PUSHING	  the	  transactions	  to	  the	  correspondents.	  	  
Assumptions	  
The	  following	  assumptions	  are	  made	  in	  regards	  to	  the	  correspondent:	  
• Correspondent	  has	  in	  place	  its	  own	  (either	  in-­‐house	  or	  vendor	  developed)	  
web	  based	  or	  other	  systems	  deployed	  throughout	  its	  payment	  points	  
(branches	  and/or	  agents)	  
• Correspondent	  has	  the	  necessary	  resources/expertise	  to	  enable	  the	  use	  of	  
Web	  Services	  as	  a	  platform	  for	  establishing	  transaction	  exchange	  interfaces	  
with	  its	  partners	  
• The	  API	  will	  be	  implemented	  at	  the	  POS	  part	  of	  its	  application	  allowing	  its	  
tellers	  to	  input	  certain	  parameters,	  which	  will	  initiate	  a	  SOAP	  call	  via	  the	  API	  
to	  Placid	  Express’	  GOPH.	  	  
• Correspondent	  agrees	  to	  use	  the	  API	  in	  conformance	  with	  the	  API’s	  User	  
Agreement

Scope	  
This	  document	  serves	  as	  an	  implementation	  reference	  designed	  for	  the	  
correspondent’s	  technical	  team	  to	  enable	  them	  to	  implement	  the	  API	  with	  the	  
correspondent’s	  remittance	  application	  platform.	  	  
The	  API	  is	  based	  on	  Web	  Services	  SOAP	  1.1	  standard.	  Most	  major	  application	  
frameworks/programming	  languages	  such	  as	  .NET,	  JAVA,	  PHP,	  C	  provides	  facilities	  
for	  utilizing	  Web	  Services.	  	  
The	  major	  components	  of	  the	  API	  are:	  
• Authentication	  
• Locating	  Transactions	  
• Processing	  Transactions	  
• Activity	  Report	  
• Manage	  locations	  
Each	  of	  the	  above	  contains	  specific	  operations	  that	  are	  explained	  in	  the	  proceeding	  
sections.	  	  
API	  Components	  
As	  stated	  in	  the	  scope,	  the	  5	  major	  components	  of	  the	  API	  are	  Authentication,	  
Locating	  Transactions,	  Processing	  Transactions,	  and	  Activity	  Reports	  &	  Managing	  
Locations.	  
Let’s	  elaborate	  further	  on	  each	  component:	  
Authentication	  
The	  authentication	  aspect	  of	  the	  API	  deals	  with	  securely	  identifying	  the	  
correspondent.	  In	  order	  to	  authenticate,	  a	  number	  of	  parameters	  must	  be	  used	  with	  
each	  instance	  of	  a	  request	  made	  via	  the	  API.	  
THE	  Authentication	  COMPONENT	  IS	  USED	  FOR	  ALL	  OPERATIONS	  of	  the	  API	  
and	  the	  routine	  is	  integrated	  within	  each	  respective	  operation.	  
The	  following	  parameters	  are	  used	  in	  the	  authentication	  aspect	  of	  every	  operation.

Note	  1:	  Populating	  Access	  Code	  
In	  order	  to	  populate	  the	  AccessCode	  field,	  you	  will	  need	  the	  following:	  
Password	  (provided	  by	  us)	  
Extra	  Value	  (Provided	  by	  us)	  
	  
Formula	  for	  supplying	  password:	  
To	  populate	  the	  AccessCode	  field,	  use	  the	  following	  formula:	  
SHA1	  (Password)	  	  
	  
IMPORTANT:	  PLEASE	  be	  sure	  to	  always	  use	  lowercase	  SHA1	  values.	  Take	  this	  
into	  consideration	  when	  concatenating	  SHA1	  values.	  
That	  just	  about	  sums	  up	  the	  authentication	  routine.	  The	  above	  routine	  would	  need	  
to	  be	  used	  with	  each	  request	  made	  via	  the	  API.	  
Note	  2:	  Terminal	  User	  
The	  terminal	  user	  is	  the	  userid	  of	  the	  teller	  conducting	  the	  payment	  request.	  
Although	  not	  strictly	  necessary,	  it	  is	  recommended	  that	  the	  actual	  teller’s	  userid	  
(the	  same	  id	  used	  to	  logon	  to	  the	  correspondent’s	  remittance	  platform)	  be	  used	  
instead	  of	  a	  single	  central	  userid.	  Should	  the	  correspondent	  desire,	  it	  can	  also	  
choose	  to	  implement/assign	  separate	  userids	  to	  all	  users	  of	  the	  API.	  	  
	  
Locating	  Transactions	  
SOAP	  Operation(s):	  	  
<LocateTX>	  
Request:	  <FetchTX>	  
Response:	  <ShowTX>	  
Locating	  transactions	  are	  the	  first	  part	  of	  processing	  a	  spotCash!	  payment.	  
Transactions	  are	  located	  by	  initializing	  a	  call	  via	  the	  API	  to	  our	  GOPH	  (Global	  Order	  
Processing	  Hub).	  Transactions	  are	  basically	  waiting	  at	  the	  GOPH	  for	  you	  to	  locate,	  
process	  and	  eventually	  disburse	  the	  funds	  associated	  with	  the	  transaction	  to	  the	  
beneficiary.	  
The	  GOPH	  does	  NOT	  authenticate	  the	  actual	  terminal	  user.	  It	  is	  used	  as	  a	  
reference	  for	  audit	  purposes.	  Should	  the	  correspondent	  wish	  to	  implement	  a	  
per	  terminal	  user	  authentication	  scheme,	  a	  separate	  lists	  of	  userids	  and	  
associated	  credentials	  would	  need	  to	  be	  exchanged	  between	  Placid	  Express	  
and	  the	  correspondent	  prior	  to	  implementation	  of	  the	  API
