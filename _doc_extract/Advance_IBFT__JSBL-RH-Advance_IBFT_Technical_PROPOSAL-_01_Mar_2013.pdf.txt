1.2 JBL Business Requirement  
 
1.2.1 As per the directives of SBP an access should be allowed to Exchange Companies and their 
Agents to process IBFT transactions directly from the interface provided to them with maker 
checker controls. In this context following is the requirement to design an interface within the 
Remit Home System to process IBFT transactions directly by Exchange Companies and their 
Agents. 
 
1.2.2 To automate the IBFT process, it is essential to have integration between RHS and IBFT option 
of JSBL internet banking; whereby transactions appearing in RHS under IBFT processing queue 
should be pushed to 1Link for title fetch and subsequent verification on T‐24 for available 
balance in Remit Home System and necessary financials in case of successful response from 
both end. 
 
1.2.3 Frontend interface similar or a customer portal should be designed within Remit Home System 
to provide limited access to Exchange Companies and their Agents to process IBFT 
transactions. 
 
1.2.4 Static maintenance option for setting up IBFT transactions limit of Agents of Exchange 
Companies per day per beneficiary should be available with maker checker control to allow 
Exchange Companies for setting up IBFT limit for their agents. 
 
1.2.5 This option will provide control to Exchange Companies to restrict execution of IBFT 
transactions beyond the limit as set by the Exchange company for each Agent. 
 
1.2.6 AGENT ROLE TO PROCESS IBFT 
- Approved Agent of Exchange Company will book IBFT by login into the Frontend interface of 
Remit Home System. 
- Once the transaction is booked and saved by  the Agent the transaction will be moved to 
“Pending for Authorization Queue” 
- In case, where Agent exceeds the per day IBFT limit granted to the Agent and maintained in 
the Remit Home System by its principle Exc hange Company, the system should not allow 
the agent to save the transaction with pop‐up message “PER DAY IBFT LIMIT EXCEEDED” 
- As soon as the transaction is booked by the Agent Exchange Company, the Remit Home 
System will send Title Fetch request to 1Link.  
- 1Link will respond to the Title Fetch request and upon successful response from 1Link, Remit 
Home System will send FT request to T ‐24 through calling API with the transaction 
description (such as transaction type, date/time and STAN) and will be saved at T ‐24 as 
input mode. 
- If the balance in the relevant Exchange Company is insufficient, then system should show a 
popup message on the Remit Home Screen that the “BALANCE IS INSUFFICIENT” 
- T‐24 system will identify the Home Remit agent transaction based on special character. 
- Designated personnel of Agent’s Principle Ex change Company will lo gin into the Frontend 
interface of Remit Home System to authorize the transaction if the transaction details are

1.3 Understanding of Scope 
 
1.3.1 RemitHome will provide new Acquisition Module for Advance IBFT functionality with the new 
User Interfaces with the real time connectivity with JS middle ware at the back end. 
 
1.3.2 Agent Mechanism will be available with the user rights for Data Entry and Authorization. 
 
1.3.3 Agent/Sub –Agent Limit Management will be available. 
 
1.3.4  Turn around Time (TAT) will be applicable between Sub‐Agent Data Entry and Agent 
Authorization level and in the event of TAT expiry; transaction will be marked as Hold.

3 Assignment Methodology 
 
3.1 Installation, Configuration, UAT and Training 
 
3.1.1 To install and configure the Software application with the help of Bank and then conduct a 
detailed walkthrough/user acceptance session to identify any issues which may cause 
difficulty during system implementation and enhance the system to the limited extent 
required to cater to such difficulties. 
 
3.1.2 User training will be provided to the designated staff. The training will comprise of a detailed 
session during which the entire system features will be demonstrated to the user. It is 
required that the prospective user is computer literate and has appropriate business 
knowledge related to the module. 
 
3.1.3 During the training session the selection of test scenarios for the exercise will be the 
responsibility of the BANK. We would suggest that some complex scenarios be selected so 
that the system is fully tested and difficulties do not arise during implementation. 
 
3.2 Pilot Implementation Support 
 
3.2.1 To provide support assistance during the pilot implementation period of specified calendar 
months. Under this, SHMA will be engaging non‐dedicated resources to analyze, recommend, 
discuss and assist in proper implementation.  
 
3.2.2 The above activity will include entering transactions on a day‐to‐day basis in the system in 
parallel to the existing system, either computerized or manual operations. The data entry and 
checking of reports at this stage will be the responsibility of the BANK, however, SHMA will 
provide assistance to the BANK’s staff in terms of investigating and sorting out any problems 
identified.   
 
3.2.3 The support assistance does not include rectification of data due to wrong data entry/process 
execution; however, SHMA will facilitate the client to rectify the same. Similarly, the support 
assistance does not include rectification of data due to malfunctioning/disturbance in the 
hardware, operating system, and form/report development tool and database engine. 
 
3.2.4 The support during pilot implementation, warranty period, maintenance and support period 
will be provided five working days a week (i.e. Monday to Friday – From 9:30 AM to 5:30 PM) 
without permanent sitting of resource person at Bank premises. 
 
3.2.5 In the case of any issues or errors/bug reported, consultant obligation shall be to exercise its 
best efforts to modify or rectify the software so as to correct the defective performance, 
within a reasonable time frame, the priority of which will be decide with mutual consent by 
the Bank and SHMA (High Priority within 2 days, Medium Priority within 4 days and Low 
Priority within 10 days).  
 
3.2.6 We do not make any warranties, expressed or implied, towards successful implementation of 
the project / software, as we understand that besides the software there are a number of 
other variables that will contribute towards an effective implementation. However as per 
tradition and practice our best efforts & resources will be deployed towards generation of 
desired results.
