S O L U T I O N  -  I N T R O D U C T I O N 
InfoBits STP - RTGS Gateway System provides the integration between Local banking software running at Bank’s 
site and “Straight through Processing (STP)” running at Central Bank. I t is the gateway between Core Banking 
System and Central Bank.  
 
Since the inception of RTGS in Pakistan, enrollment of direct participants is growing and volume of transactions 
is also increasing. It has been foreseen that in future, volume of transaction will increase dramatically. This 
growing volume forcing banks to deploy a gateway application between Core Banking System and Central Bank 
to improving performance of financial messages communications channels. 
 
The requirement is initiated by JS Bank that a gateway application system between Core banking and State Bank 
of Pakistan wh ich will act as local STP RTGS solu tion for MT103/MT102/MT202  messages. It will also be a 
repository of messages exchanged between State Bank of Pakistan and JS Bank and provide reports for audit and 
reconciliation. There are three modules in InfoBits RTGS Gateway Application  
 
1. Outward message routing  
2. Inward message routing  
3. Reporting module

Methodology  
InfoBits STP-RTGS Gateway Application is centralize repository for a bank and State Bank of Pakistan for outward 
and inward messages. It is the gateway between Core Banking Application and State Bank of Pakistan’s PRISM; 
the application will pull and push messages from Core Banking Application and State Bank of Pakistan’s messages 
folders through RCCC API communication channel . The application handles two types of message channel 
communication. 1. Outward message 2. Inward message

Inward message routing  
 
 
MT103, MT202 and MT202 
(1) InfoBits RTGS Gateway  application will collect financial messages from Central bank’s PRISM System’s 
message repository through RCCC API data stream communication channel. 
(2) All financial messages will be placed in processing queue for Operator to validated beneficiary account 
number and account title from core banking application database (through core banking API). 
(3) Once the account information provided in inward financial message  is validated from core banking 
application database, operator will process the message for authorization. 
(4) Authorizer will review the message and authorize the transaction for further processing. 
(5) All authorized transactions will posted in the system and accounting will be performed in core  banking 
application (through core banking API). 
 
InfoBits STP-RTGS Gateway application will also send email intimation for all incoming messages to respective 
branch or group along with original message attached automatically. 
 
Outward message  
 
MT103, MT202 and MT 202 
(1) All financial messages will be prepared on InfoBits RTGS Gateway application’s operator interface. Once 
the message is prepared, it will be send to authorization queue. 
(2) Authorizer will review the messages and authorize the transactions for further processing. 
(3) All authorized transactions will posted in the system and accounting will be perfor med in core banking 
application database (through core banking API). 
(4) Once accounting is performed successfully in core banking application  database (through core banking 
API), the transactions will be transmitted to Sate Bank’s RTGS System (PRISM) through RCCC API data 
stream communication channel. 
 
InfoBits RTGS Gateway  application will  also send email intimation for all successful/Unsuccessful messages 
delivery report to respective branch or group along with original message attached automatically.

Online monitoring queue  
Online monitoring queue for all incoming 
and outgoing messages, will be available 
with a status-wise drop down list 
 
 
Message Queue  
InfoBits RTGS Gateway Application removes 
the unprocessed messages from queue 
after cut-off time specified by JS Bank and 
generate a report. Intimation will also be 
generated for such removal via e mail. Records of all expired messages will be available in the system for future 
reference only. 
 
 
Parameterized scheduler  
User can set message cutoff time in application. Application will sent message to Central Bank’s message 
repository as per define cutoff time and after that application will remove the message from the transfer queue.  
 
 
Reporting module  
Comprehensive reporting module is also available for printing message confirmations; acknowledgements to 
their respective department/Branches/user groups.
