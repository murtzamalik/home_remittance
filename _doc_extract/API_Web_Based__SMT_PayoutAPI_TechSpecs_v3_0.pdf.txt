SMT Payout API Version 3.0 
 
 
1 Introduction 
Sigue Money Transfer (SMT) has developed an online Application Programming Interface 
(API) to allow partners to connect the Sigue processing engine using their own front-end 
transaction capture application. The API offers all the required functional interface methods 
to allow partners to capture, submit and view transactions with SMT. 
 
1.1 Scope of this document 
This document will describe what the SMT API interface is designed to do and how it can be 
used. It also contains technical information to provide a general working direction for the 
Payout Partner. 
 
The document also lists the Usage Policies and Guidelines. 
 
The document includes a Change Summary section for the benefit of existing partners so 
they can focus on the incremental changes. 
 
The Testing and Certification process is described at a high level. 
 
In the Appendix, sample codes and reference XML files have been included for illustration.

1.2 Usage Policies and Guidelines 
The contents of this document describe the Sigue Payout API implementation. However, 
both the API implementation and this document are subject to change based on business or 
technical requirements. Before commencing any integration development please check with 
the email id provided on the cover page for the latest version. 
 
Partners should base their development of the interface on the live WSDL that will be 
provided by SMT upon request after an NDA or contract is signed and development by the 
partner is about to start. 
 
All enhancements and modifications to the API will be classified as Mandatory and Optional. 
 
Mandatory changes are generally as a result of regulatory or business process changes or 
technical issues. Partners will have to make the mandatory changes within the specified 
timeframe, without which they may not be able to connect to Sigue systems to execute 
transactions. Partners will be given as much notice as possible, however, based on the 
nature of the change and its implications, the notice may be short. 
 
Optional changes are generally enhancements to offer new and enhanced features. Partners 
are encouraged to implement these changes at the earliest to take advantage of the new 
features, however, no deadlines will be enforced.

1.3 Connecting to the Sigue Payout API 
There are two versions of the Sigue Payout API, test and production. 
 
The test version is to be used by partners to ensure their application is working fine, before it 
is released to production. Sigue follows a comprehensive testing and certification process, 
on the successful completion of which, partners are granted access to the production 
system. Please see the section on Testing and Certification. 
 
The production version is to be used by partners when they are ready to start sending live 
transactions to Sigue. 
 
Access to the Sigue environments will be provided to appropriate partner environments. The 
test environment may only be access by the partner test environment and the production 
environment may only be accessed by the partner production environment. It will not be 
possible to provide access to the two environments from the same server on the partner 
side. Which means partners are expected to maintain a minimum of two servers, one for 
development and testing and one for production. 
 
Access to both environments requires network and application level access credentials 
which can be obtained once all the on-boarding formalities are completed. 
 
Once a development and testing schedule has been agreed upon, you will be provided with 
the following information: 
 
 The URL to access the Test API environment 
 Access credentials 
 
SMT requires the following information from partners: 
 
 One or more public static IP address for development and testing servers. Please 
note that requests only from this IP address will be able to connect to the Sigue API 
environment. 
 
The SMT API builds on the standard Web Services model to provide security for messages 
from and to partner applications.  Access to the API is over a secure HTTP (https) 
connection and all data traffic will be encrypted using SSL.

3 API Methods Summary List 
The SMT Payout API is meant for use by all Payout Partners who would like to use their own 
transaction capture application. The API supports all SMT products, currently including Cash 
Pickup, Account Deposit and Cash Delivery. 
The SMT Payout API provides the following functional methods. 
 Get Country Codes 
This method is used to download standard 3 alphabets country ISO code. 
 
 Get Currency Codes 
This method is used to download standard 3 alphabets currency ISO code. 
 
 Get ID Types 
This method is used to request a list of all the ID types SMT uses. 
 
 Get Response Codes 
This method is used to download up to date response codes generated by the API. 
 
 Get Settlement Report 
This method is used to request a settlement report, provided the settlement process 
has been run for that period. The method only allows retrieving the settlement report 
no more than 3 months old. 
 
 Get Settlement Report USD 
This method is used to request any settlement report on demand, provided the 
settlement process has been run. This method provides settlement values and FX 
revenue details in USD. The method only allows retrieving the settlement report no 
more than 3 months old. 
 
 Nominated Payout Query 
This method is used to pull down all transactions that are nominated to be paid and 
cancelled. The API method retrieves only the transactions that the agent can mark as 
paid, acknowledged or canceled. 
 
 Nominated Payout Update 
This method allows partner to do the followings: 
- Partner will consume API method NominatedPayoutUpdate to send acknowledge 
status for each transaction that should be paid. 
- Partner will consume API method NominatedPayoutUpdate to send cancellation 
confirmation for each transaction that can be cancelled. 
- Partner will consume API method NominatedPayoutUpdate to send cancellation 
refused for each transaction that can’t be cancelled. 
 
 Payout Search By Name (for Cash transactions only) 
This method is used to request the details of a specific transaction to pay out, using 
the beneficiary’s last name and the originating country for the transaction. The 
partner application will provide valid values for the required parameters, and the 
system will validate the request against the business rules for a payout. If valid, the

full transaction details will be returned. The message will apply to transactions which 
can be paid out in cash only. 
 
 Roll Back Paid Transaction 
This method is used to rollback a transaction to its previous state. This will usually 
occur if the partner encounters an error on their system after they have paid out a 
transaction. The request to rollback a transaction will not always be granted but a 
reason will be given. 
 
 Work Flow Payout Query 
This method is used to retrieve the details of any transactions which require an 
Account Deposit and Courier Delivery payout service. The frequency with which the 
partner application calls this service will be agreed with the partner on a case by case 
basis, as it cannot be enforced or controlled by the SMT system. 
 
 Work Flow Payout Query New 
This method is used to retrieve the details of any transactions which require an 
Account Deposit and Courier Delivery payout service. The frequency with which the 
partner application calls this service will be agreed with the partner on a case by case 
basis, as it cannot be enforced or controlled by the SMT system. 
 
 Work Flow Payout Update 
This method is used to send an update for an Account Deposit or Cash Delivery 
transaction, for which the details have previously been obtained using the Workflow 
Payout Query. Reasons for update will include: 
- Confirmed Successful Payout 
- Acknowledgement of Transaction resulting from Workflow Payout Query 
- Confirmation of cancellation (as result of Send Agent’s request) 
- Refer back to sending agent (problem with account detail or incorrect address) 
 
 Payout Query (for Cash transactions only) 
This method is used to request the details of a specific transaction to pay out, using 
the SMT transaction number or any other partner-specific payout number (if 
supported). The partner application must provide valid values for the required 
parameters. The system will validate the request against the business rules for a 
payout. If valid, the full transaction details will be returned. The message will apply to 
transactions which can be paid out in cash only. 
 
 Payout Update 
This method is used to send an update for an SMT cash transaction, for which details 
have previously been obtained using the Payout Query method.  
Reasons for update would include: 
- Payout 
This will be validated against the business rules for paying transactions. It is the 
equivalent of the Payout screen. 
- Payout Confirmation 
This is an optional step where Payout partner wish to have a confirmation or 
commit step in the process of paying out a transaction.

3.1 General Features 
For Cash Pickup Transactions 
- The ability to identify SMT transactions which are intended to be paid out in a specific 
country. Transactions will be able to be paid out by any Payout Partner, on a first-come, 
first-serve basis. 
- The ability for the Payout Partner to provide a SMT or other external payout number 
(given to them by a recipient requiring payout) and request the detail of the transaction to 
be paid out. 
- As part of the response to the payout request, SMT will have the ability to validate the 
payout request against business rules and provide the details to the Payout Partner. 
- The ability for the Payout Partner to update SMT with changes in payout status of the 
transaction. 
- In order to minimize processing around Cancellations/Payout to Originator, SMT will not 
provide full payout transaction details to the partner for Cash transactions in advance, 
only at the time of actual payout. 
 
For Account Deposit and Cash Delivery Transactions 
- The ability for Payout Partner to retrieve details of transactions for payout, thus entering 
the transaction into the normal SMT workflow processing. 
- The ability for the Payout Partner to update SMT with changes in payout status of the 
transaction. 
- The process for SMT to communicate cancellation requests to the Payout Partner by 
means of online messages (initiated by a Send Agent rather than SMT Operations).  
- The ability for Payout Partners to refer transactions back to sending agents. 
- Some Payout Partners may require SMT to use the partner’s own payout reference 
number. This option will be made available via the API on a case-by-case basis.

Appendix A: Testing and Certification 
On confirmation that the partner has completed development, SMT will share a testing and 
certification test plan. The plan includes a comprehensive list of test cases along with test 
data. 
 
The partner should execute all the test cases and submit the results to the Sigue QA team. 
These will be compared with the expected results and feedback provided to the partner. 
 
Once all test cases have been successfully executed, the QA team will certify the integration 
ready for production deployment. 
 
Partners are expected to execute their own test cases in addition to those provided by Sigue 
to ensure everything works fine from their end.

Appendix C: Transaction Status Codes 
SMT has several send and payout status for transactions held in the SMT system. The 
following statuses of transactions are the most commonly used and can be shown in the 
reports produced by SMT and the API message responses. 
 
Status Code Meaning 
PP If the transaction has been stopped by Compliance check. 
SQ If the transaction is confirmed suspicious and will not be released until 
sending agent is contacted. 
CN When the transaction has been cancelled. 
CP When the transaction has been sent and is ready for payout. 
IP When the transaction is in an incomplete status or in progress. These 
can happen if: 
The transaction was not completed properly by the Send Partner. 
SMT sent the transaction it to an outside payout partner (via a payout 
interface) and SMT is waiting from payment confirmation. 
The Send Partner did not confirm the send transaction 
PD When the transaction has been paid to the customer, SMT will send 
status 'PD' 
PO When the transaction has been paid back to the originator (i.e. 
cancellation without fees). 
RF When the payout agent has refused to make the payment due to 
insufficient id or other reasons. This is a payout status only and is in 
combination with a send status of 'CP'.
