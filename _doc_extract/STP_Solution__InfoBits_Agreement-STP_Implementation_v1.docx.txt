SOLUTION INTRODUCTION
InfoBits STP - RTGS Gateway System provides the integration between Local banking software running at Bank’s site and “Straight through Processing (STP)” running at Central Bank. It is the gateway between Core Banking System and Central Bank. 
Since the inception of RTGS in Pakistan, enrollment of direct participants is growing and volume of transactions is also increasing. It has been foreseen that in future, volume of transaction will increase dramatically. This growing volume forcing banks to deploy a gateway application between Core Banking System and Central Bank to improving performance of financial messages communications channels.
The requirement is initiated by JS Bank that a gateway application system between Core banking and State Bank of Pakistan which will act as local STP RTGS solution for MT103/MT102/MT202 messages. It will also be a repository of messages exchanged between State Bank of Pakistan and JS Bank and provide reports for audit and reconciliation. There are three modules in InfoBits RTGS Gateway Application 
1. Outward message routing 
2. Inward message routing 
3. Reporting module
Methodology 
InfoBits STP-RTGS Gateway Application is centralize repository for a bank and State Bank of Pakistan for outward and inward messages. It is the gateway between Core Banking Application and State Bank of Pakistan’s PRISM; the application will pull and push messages from Core Banking Application and State Bank of Pakistan’s messages folders initially through “SBP Controller Application” and after deployment of InfoBits Operator Application, RCCC API communication channel will deployed and used in replacement of SBP Controller Application. 
Overall Straight through Processing (STP) Project has been divided into three Phased 
Phase-I Compliance of Home Remittance (March 31, 2016)
Outward
Remit Home Application user will export all outward messages and will be placed in “Out RemitHome Folder” manually
Message in annexure “B” format, will extracted by “InfoBits Gateway App” from “Out RemitHome Folder” and converted into MT102 format and will be place in “Outward Message Folder” accessible to “SBP Controller Application” automatically.
“SBP Controller Application” user will import all MT102 messages from “Outward Message Folder” and transmit the message to SBP RTGS system using “SBP Controller Application”
Inward
“SBP Controller Application” user will export all incoming MT102 messages from “SBP Controller Application” and will placed into “Inward Message Folder” using “SBP Controller Application – Export Option” manually.
InfoBits Gateway App will extracted all inward MT102 messages from “Inward Message Folder” and will convert into annexure “B” format and will be place all those messages into  “Inward RemitHome Folder” automatically.
Through business as usual, Remit Home Application user will import all inward messages available in “In RemitHome Folder” manually.
Phase – II Deployment of Message Creation Application 
In this phase following application modules will be deployed and tested;
InfoBits Integration Engine to integrate Core Banking Application with RTGS Gateway Application will be deployed and tested for Inward and Outward messages.
Financial/Accounting entries posting mechanism will also be developed and deployed according to the requirement narrated by JS Bank.
Deployment of InfoBits Controller Application for message creation will also be the part of this phase.  
Phase – III   Deployment of RCC Communication Channel in replacement of SBP Controller (Project Finalization) 
Phase – III   
Following End-To-End STP approach will be adopted for Inward message routing and outward message routing 
Inward message routing 
MT102, MT103 and MT202
InfoBits RTGS Gateway application will collect financial messages from Central bank’s PRISM System’s message repository through RCCC API data stream communication channel.
All financial messages will be placed in processing queue for Operator to validated beneficiary account number and account title from core banking application database (through core banking API).
Once the account information provided in inward financial message is validated from core banking application database, operator will process the message for authorization.
Authorizer will review the message and authorize the transaction for further processing.
All authorized transactions will posted in the system and accounting will be performed in core banking application (through core banking API).
InfoBits STP-RTGS Gateway application will also send email intimation for all incoming messages to respective branch or group along with original message attached automatically.
Outward message 
MT102, MT103 and MT202
All financial messages will be prepared on InfoBits RTGS Gateway application’s operator interface. Once the message is prepared, it will be send to authorization queue.
Authorizer will review the messages and authorize the transactions for further processing.
All authorized transactions will posted in the system and accounting will be performed in core banking application database (through core banking API).
Once accounting is performed successfully in core banking application database (through core banking API), the transactions will be transmitted to Sate Bank’s RTGS System (PRISM) through RCCC API data stream communication channel.
InfoBits RTGS Gateway application will also send email intimation for all successful/Unsuccessful messages delivery report to respective branch or group along with original message attached automatically.
Online monitoring queue 
Online monitoring queue for all incoming and outgoing messages, will be available with a status-wise drop down list
Message Monitoring Queue 
InfoBits RTGS Gateway Application removes the unprocessed messages from queue after cut-off time specified by JS Bank and generate a report. Intimation will also be generated for such removal via e mail. Records of all expired messages will be available in the system for future reference only.
Parameterized scheduler 
User can set message cutoff time in application. Application will sent message to Central Bank’s message repository as per define cutoff time and after that application will remove the message from the transfer queue.
