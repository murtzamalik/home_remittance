Customer’s Requirement
An effective Home Remittance Solution enables the banking institution to operate a service targeting to the nationals of their country who are working and living abroad, helping them send funds to home cost-effectively. (who whom), it addresses the needs of a growing set of banked customers who require easy,  cost-effective,  secure and reliable international inward funds transfer. 
Home Remittance System
With the evolving trends of globalization and efficient customer service, virtually every business unit is in stride to cope with the emerging challenges. This task becomes more vital for financial bodies as not even marginal delay, inefficiency or non-connectivity would be tolerated particularly by customers. Financial bodies, during this chase of efficient, timely yet secure services to customer, have to also look for businesses being initiated by correspondent market players or banks. 
Just looking at the businesses being offered by them would not assist any particular financial body or bank in the voyage of success. For this, every market player should facilitate the business being offered by correspondent banks so as to remain in quest of excellence and overall profitability.
CRPL offers a perfect blend of Remittances & Payment process within one package through managed reconciliation, i.e. reconciling the right Remittance Advice with the right payment.

Sub Agent Area
Sub Agents are responsible for collecting information related to beneficiary account title, Bank and Amount to be remit. 
Sub Agent will validate/complete the account details (IBAN/BAN) using SSO A/C enquiry Module 
Sub Agent will enter the amount to be remit, which should be in the defined limit. 
Sub Agents per transaction limits will be maintained though user/limit management module.
The next step is to get more detailed and complete information of the beneficiary, the requested amount and IBFT member bank name, where beneficiary maintains his/her account. Complete remitter’s information is also maintained. Since Beneficiary and relevant account has already been verified therefore upon completion of this step:
Agent account is debited
Transaction ID created
Transaction is available to principal agent for authorization
Payable created, after authorization
Countdown for Authorization starts (30 Minutes – time is configurable)
Principal Agent Area
Principal agent is responsible for either Authorizing or Rejecting the transaction data received from Agent. This authorization or rejection should be done within defined time limits (30 Minutes – time is configurable), else transaction will be cancelled/blocked. Amount of cancelled and blocked transactions will be revered to agent’s account accordingly. Blocked transactions can only be restored by Bank.
The data is then at its final stage, since BAFL is linked with IBFT member banks. Those beneficiaries having account in any other member IBFT banks are accordingly facilitated by them.

API Web Service
Process flow for API Web Service is narrated below:
Remitter visits Agent’s office 
Remitter provides Beneficiary Account number
Receiving agent verifies the “Account Number” using API Web Service title fetch
If “Beneficiary Account” is valid:
Agent input further transaction details
Transaction status will be marked as PAID using API Web Service
API verify and validate amount availability
If amount is available, Web Service API calls Core Bank API to debit Agent account and credit beneficiary account
Upon successful transaction execution, Cash Management Payment System is updated and SMS is sent to beneficiary also Agent paid confirmation is marked
 The key Features are: 
Real time credit to beneficiary account 
Fully Automated process through integration of systems between both institutions 
Immediate credit confirmation through SMS 
No double entry required in core bank and agent interface to remove reconciliation issues

Online Agent Connect 
Actual process flow followed for remittance through “Online Agent Connect” will be as:
Beneficiary visits branch with XPIN
Teller verifies the XPIN for validity
If the PIN number is verified, agent is verified via agent web service
If agent is verified successfully, transaction details are displayed
Transaction status is checked:
If status marked as cancelled, payout is declined
If status marked as paid, payout is declined
If status marked as unpaid, agent is given the response to payout transaction
If the Transaction falls within teller limit it is marked as paid
Else will be routed to Authorizer to first get authorized
Beneficiary account is credited, agent updated & Core bank updated

Transaction File Workflow
PRI, RTGS (Rs.1 Million minimum limit should be consider), MT 103 and Customizable File format Transaction files can be uploaded into the system via:
Pull FTP
Email
Push FTP
Once the payment instructions are uploaded into the system, compliance screening of transaction with UNSC, OFAC and other local lists (NAB) is performed. If the Remitter or the beneficiary’s name is matching in any of the list, transaction should be segregated and held for further verification.
Afterwards Data Cleansing activities are performed on the data: 
Bank Identification: Required if bank Name is not mentioned in Payment instructions 
Branch Identification: Required if Branch is not mentioned and account number is also incomplete 
Data segregation: Required if payment type is not mentioned or Change is required in Payment Mode  
Account Completion: Required where account numbers are incomplete 
Data Publishing 
COC Transactions: System will pay the transaction to the beneficiary account using BAN. 
Other Bank transactions: can be processed through IBFT, PRI or Demand Draft depending on the nature of transaction.
