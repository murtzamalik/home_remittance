S O L U T I O N  -  I N T R O D U C T I O N  
InfoBits STP - RTGS Gateway System provides the integration between Local banking software running at Bank’s 
site and “Straight through Processing (STP)” runnin g at Central Bank. It is the gateway between Core B anking 
System and Central Bank.  
 
Since the inception of RTGS in Pakistan, enrollment of direct participants is growing and volume of transactions 
is also increasing. It has been foreseen that in fu ture, volume of transaction will increase dramatica lly. This 
growing volume forcing banks to deploy a gateway application between Core Banking System and Central Bank 
to improving performance of financial messages communications channels. 
 
The requirement is initiated by JS Bank that a gateway application system between Core banking and State Bank 
of Pakistan which will act as local STP RTGS soluti on for MT103/MT102/MT202 messages. It will also be a 
repository of messages exchanged between State Bank of Pakistan and JS Bank and provide reports for audit and 
reconciliation. There are three modules in InfoBits RTGS Gateway Application  
 
1. Outward message routing  
2. Inward message routing  
3. Reporting module

Phase-I Compliance of Home Remittance (March 31, 2016) 
 
Outward 
• Remit Home Application user will export all outward messages and will be placed in “Out RemitHome 
Folder” manually 
• Message in annexure “B” format, will extracted by “InfoBits Gateway App” from “Out RemitHome 
Folder” and converted into MT102 format and will be place in “Outward Message Folder” accessible to 
“SBP Controller Application” automatically. 
• “SBP Controller Application” user will import all MT102 messages from “Outward Message Folder” and 
transmit the message to SBP RTGS system using “SBP Controller Application” 
Inward 
• “SBP Controller Application” user will export all incoming MT102 messages from “SBP Controller 
Application” and will placed into “Inward Message Folder” using “SBP Controller Application – Export 
Option” manually. 
• InfoBits Gateway App will extracted all inward MT102 messages from “Inward Message Folder” and 
will convert into annexure “B” format and will be place all those messages into  “Inward RemitHome 
Folder” automatically. 
• Through business as usual, Remit Home Application user will import all inward messages available in 
“In RemitHome Folder” manually.

Phase – III    
Following End-To-End STP approach will be adopted for Inward message routing and outward message routing  
Inward message routing  
 
 
MT102, MT103 and MT202 
(1)  InfoBits RTGS Gateway application will collect fina ncial messages from Central bank’s PRISM System’s 
message repository through RCCC API data stream communication channel. 
(2)  All financial messages will be placed in processing  queue for Operator to validated beneficiary accoun t 
number and account title from core banking application database (through core banking API ). 
(3)  Once the account information provided in inward fin ancial message is validated from core banking 
application database, operator will process the message for authorization. 
(4)  Authorizer will review the message and authorize the transaction for further processing. 
(5)  All authorized transactions will posted in the syst em and accounting will be performed in core banking  
application (through core banking API ). 
 
InfoBits STP-RTGS Gateway application will also sen d email intimation for all incoming messages to res pective 
branch or group along with original message attached automatically. 
 
Outward message  
 
MT102, MT103 and MT202 
(1)  All financial messages will be prepared on InfoBits RTGS Gateway application’s operator interface. Once 
the message is prepared, it will be send to authorization queue. 
(2)  Authorizer will review the messages and authorize the transactions for further processing. 
(3)  All authorized transactions will posted in the syst em and accounting will be performed in core banking  
application database (through core banking API ). 
(4)  Once accounting is performed successfully in core b anking application database ( through core banking 
API ), the transactions will be transmitted to Sate Ban k’s RTGS System (PRISM) through RCCC API data 
stream communication channel.
